## Semântica e regressões independentes

`optional` não implica `nullable`; recusados: nulidade não permitida, objetos/listas aninhados malformados, campos de outra variante, inteiros acima de 2^53−1 e boolean como inteiro. Strings usam bytes UTF-8; conteúdo base64 tem limite por bytes decodificados. MCP discrimina por `tool`. PermissionAction cobre command/edit/question/forge.

Regressões independentes acrescentadas pela revisão: `AC-permission-command-valid`, `AC-permission-command-missing-details`, `AC-permission-wrong-nested-type`, `AC-permission-cross-variant`, `AC-runtime-empty-snapshot`, `AC-runtime-malformed-receipt`, `AC-threads-missing-singleton`, `AC-snapshot-null-cursor`, `AC-runtime-dispatch-duplicate-equal`, `AC-runtime-dispatch-command-id-mismatch`, `AC-runtime-dispatch-revision-mismatch`, `AC-json-safe-integer-max`, `AC-json-safe-integer-overflow`.

## Decisão de limite efetivo

`PermissionRequest.options` declara `maxItems: 100`, enquanto o variant `question` de `PermissionAction.options` declara `maxItems: 10` e os dois campos devem ser iguais. Portanto o limite semântico de um PermissionRequest question é 10; casos de borda efetiva testam 10 e 11. Para requests dos demais variants, ambos os arrays ficam vazios.
